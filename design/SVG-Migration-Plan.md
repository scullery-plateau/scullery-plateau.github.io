# SVG Migration Plan

The Scullery Plateau ecosystem is moving from a JSX-driven rendering model to a **Pure String-Based Rendering Architecture**.

## Objectives
1. **Performance**: Bypass React Virtual DOM diffing for complex SVG structures.
2. **Consistency**: Use the exact same SVG string for both the browser preview (Sink) and the print-ready HTML export.
3. **Architecture**: Establish a "Renderer" as a single source of truth for SVG output per application.

## Phase 1: Standardize the Renderer (In Progress)
- [x] Refactor core `Renderer` classes to output raw SVG strings.
- [x] Standardize on `<use>` and `<defs>` patterns for performance.
- [x] Implement orientation and canvas-agnostic rendering.

## Phase 2: React Bridge (The "Sink")
- [ ] Establish the `dangerouslySetInnerHTML` pattern as the project-wide standard for SVG.
- [x] Audit `apps/common/svgClick.js` to ensure reliable event dispatching.
- [ ] Create a reusable utility for click-handling inside SVG strings.
  - Integrate `sp.common.SVGClick` for bridge-based events.
  - Implement pattern: `<rect onclick="window.svgClick('eventName', 'id')">`.
  - Enforce constraint: `svgClick` dispatcher only accepts 'click' events or <a> tags.

## Phase 3: Application Migration
For each app in `/apps`, perform the following:
1. **Renderer Conversion**: Extract JSX-based SVG rendering logic into a pure string-generating `Renderer`.
2. **Component Refactor**: Replace JSX SVG structures in React components with a container div using `dangerouslySetInnerHTML`.
3. **Interactive Bridge**: Inject `onclick` handlers into strings generated by the `Renderer` to maintain interactivity without React event handlers.
4. **Cleanup**: Remove unnecessary local CSS/SVG-related styles that are now handled by the agnostic rendering engine.

## Migration Targets
- [ ] `apps/overlander`: Map hex rendering to string generation.
- [ ] `apps/outfitter`: Composite layer rendering to string generation.
- [ ] `apps/spritely`: Pixel grid rendering to string generation.

## Best Practices
- **Never render SVG in JSX**: If it involves path data or complex shapes, keep it in a pure string renderer.
- **Maintain Parity**: The library `landscape.css` and `portrait.css` are the source of truth for print layout.
- **Consistency**: All renderers must output a consistent "Print Package" structure: `{ title, orientation, defs, pages }`.
